# Ежедневная сводка support-отдела: CRM + рабочие чаты → список дел

Тестовое задание для Руссмаркет (специалист по AI-автоматизации).

**Идея.** Всё, что можно проверить детерминированно (даты, статусы, сроки), проверяют правила.
Модель только классифицирует сообщения из чатов: что в них утверждается.
Сообщение из чата никогда не закрывает задачу и не снижает срочность — подтверждение есть только в CRM.

```
CRM + сообщения из чатов
  → маскирование ПДн (телефоны, почта, карты, паспорта)
  → модель: тип утверждения + новое время + «передано в личку» (строгий JSON по схеме)
  → проверка ответа кодом; сбой → кейс уходит в «прочитать вручную», а не пропадает
  → правила: уровень срочности, порядок, действия
  → сводка (markdown) и сообщение в Telegram; цитаты из чата — дословно
```

## Запуск

Только стандартная библиотека Python 3.9+, `pip install` не нужен.

```bash
python3 summary.py data/cases.json                   # четыре кейса из задания (записанные ответы модели, ключ не нужен)
python3 summary.py data/edge_cases.json              # шесть пограничных кейсов
python3 -m unittest -v                               # 22 теста правил (модель заменена заглушкой)

cp .env.example .env                                 # OPENAI_API_KEY, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
python3 summary.py data/cases.json --mode live       # реальный вызов модели
python3 summary.py data/cases.json --mode live --record   # + перезаписать fixtures/
python3 summary.py data/cases.json --send            # + отправить сводку в Telegram
```

На macOS с Python с python.org: `pip install certifi` — скрипт подхватит сертификаты сам.

## Файлы

| Файл | Что внутри |
|---|---|
| `summary.py` | правила, инструкция и схема ответа модели, маскирование ПДн, рендер, Telegram |
| `data/cases.json` | четыре кейса из задания (понедельник, 10:00) |
| `data/edge_cases.json` | пограничные кейсы |
| `fixtures/llm_responses.json` | ответы модели из живого прогона; в `_meta` — модель и время записи |
| `test_summary.py` | тесты правил |
